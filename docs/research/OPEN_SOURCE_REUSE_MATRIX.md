# Open-Source Reuse Matrix

- Review date: 2026-08-17
- Scope: architecture patterns for a Windows-first, local-only TypeScript product
- Evidence rule: canonical repositories and official documentation only

No vendor repository was copied into OpenDashboard. “Reuse” below means adopting a small interface or lifecycle pattern unless a dependency is explicitly approved.

## Windows ownership sources

Future real actions must use more than a PID. Primary platform contracts are [`Win32_Process`](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process), [`Win32_Process.GetOwner`](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/getowner-method-in-class-win32-process), [`Win32_Service`](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-service), and [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). PID reuse, inaccessible owner data, executable path changes, session changes, and service-account mismatch must all cause denial.

## Final reuse decision

PF1 adds no upstream runtime dependency. It implements the closed TypeScript contract needed to migrate one existing provider, using independently authored code and the lifecycle principles above. The first dependency candidate is `systeminformation`, and only in a separately reviewed read-only adapter. Cordis or Extism adoption requires a measured spike and an explicit removal of equivalent local code before either enters the runtime.
