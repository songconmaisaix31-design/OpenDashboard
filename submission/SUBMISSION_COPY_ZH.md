# OpenDashboard 参赛简介

## 一句话介绍

OpenDashboard 把一次可重复的本地 API 故障，转化为可解释证据、需要明确审批的模拟恢复，以及一份脱敏审计记录。

## 简介

OpenDashboard 面向需要同时管理多个本地服务的 AI 原生开发者。竞赛版本用 90 秒展示 `order-api` 从降级到恢复的完整路径：先收集已脱敏的 HTTP、追踪、日志和资源证据，再运行只读 `api-500-triage`，申请并批准一次模拟托管运行时重启，验证固定样例恢复，最后导出脱敏报告。

这个范围刻意保持狭窄。评审可以清楚看到：为什么提出操作、是否记录了样例审批事件、状态发生了什么变化、哪些数据来自模拟，而不需要在多套工具之间切换，也不需要相信不透明的自动化步骤。

## 能力边界

- 已实现：五阶段可重复引擎、中文引导界面、审批门、恢复验证、重置和证据导出。
- 明确模拟：Cordis、LocalOps、Agent Usage Manager、FastAPI Radar、Hardware、Orca 和 AgentTeams 的竞赛数据全部来自固定样例，不是实时集成。
- 已延期：实时提供器、真实进程控制、任意 Shell、可执行插件、外部请求、部署和多人生产运行。

## 必须保留的真实性声明

演示故障是固定样例持有的临时故障锁，不是源代码缺陷。批准只确认一次模拟样例操作，随后由恢复验证清除样例故障锁。两者都不会重启真实进程、修复代码、连接外部服务，也不能证明生产可用性。
