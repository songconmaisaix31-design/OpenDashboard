## Integration contract

- Call `createFixtureDataSource()` once per isolated demo session. It returns
  the frozen `DemoDataSource` interface and exposes no provider-specific data.
- `loadInitialSnapshot()` returns a detached copy of the source's current
  in-memory state. A new source starts at `incident_open`; only `resetDemo`
  resets an existing source.
- Consumers obtain `runId`, incident, target, and approval references from the
  returned snapshot instead of importing fixture constants.
- Every command returns the contract's discriminated success or error result.
  Reference validation and phase validation produce stable error codes without
  mutating engine state.
- An accepted idempotency key is retained for the fixture run. Replaying the
  same command and input returns its original value with `replayed: true`;
  reusing the key for different input returns `idempotency_conflict`.
- `resetDemo` restores the same deterministic IDs and timestamps. A new journey
  after reset must use new idempotency keys; replaying an old accepted key still
  returns its original result by design.
- `exportEvidence` returns a redacted in-memory `DemoEvidenceReport`. It does
  not write a file, send a request, control a process, or claim live execution.
