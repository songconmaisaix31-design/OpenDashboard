## Integration contract

T2 consumes only the frozen `DemoDataSource` port from
`apps/web/src/contracts/**`. It does not import T1 domain, fixture, state-machine,
or provider files.

- `App({ dataSource?: DemoDataSource })` is the composition seam. Without an
  adapter, it renders an honest integration-boundary state.
- `GuidedDemoPage({ dataSource: DemoDataSource })` loads the initial snapshot,
  invokes frozen commands, renders discriminated failures, and accepts only
  normalized contract results.
- T4 must instantiate the T1 fixture data source and pass it to `App`; runtime
  composition is intentionally absent from the T2 commit.
- UI command mapping is fixed and explicit:

| Phase | Port command |
|---|---|
| `incident_open` | `collectEvidence` |
| `evidence_collected` | `requestRestart` |
| `approval_pending` | `approveAction` |
| `action_confirmed` | `verifyRecovery` |
| `recovered` | `exportEvidence` |

Command idempotency keys use `runId`, a local reset-cycle counter, and the command
name. Evidence-export keys also include the current phase so a report inspected
before recovery cannot be replayed as the final recovered report. Retries within
one phase reuse the key; a successful reset advances the cycle.
Contract error messages are mapped to bounded UI copy instead of rendering raw
provider text.

`apps/web/tests/e2e/preview-data-source.ts` is a test-only screenshot stub. It
returns prebuilt T0-compatible snapshots and does not validate inputs, implement
domain transitions, or replace the T1 fixture engine.
