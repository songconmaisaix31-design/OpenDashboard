## Integration contract

The current runtime source of truth is the strict TypeScript contract, not the
older planning snippet in `API_CONTRACT.md`:

- Port: `apps/web/src/contracts/data-source.ts` — `DemoDataSource` with explicit
  command inputs, deterministic `idempotencyKey`, and discriminated
  `DemoCommandResult<T>` failures.
- Fixture entry: `apps/web/src/demo/index.ts` —
  `createFixtureDataSource(): DemoDataSource`.
- Presentation seam: `apps/web/src/pages/App.tsx` — `App({ dataSource })` passes
  only the normalized port to `GuidedDemoPage`.
- Production composition: `apps/web/src/main.tsx` — one adapter instance per
  page load, outside React rendering, then `<App dataSource={dataSource} />`.

This keeps provider-specific fields out of the UI and gives a future adapter a
single replacement boundary. The competition candidate enables only the local
fixture implementation.

## Known gaps and boundaries

No P0 runtime blocker remains for the deterministic local fixture demo. The
following issues require a separately scoped owner rather than an out-of-bounds
T4 edit:

- `API_CONTRACT.md` is still a v0.1 planning document whose method examples omit
  `idempotencyKey` and `DemoCommandResult<T>`. Future adapters must implement
  `apps/web/src/contracts/**` until the T0 contract document is aligned.
- `AppProps.dataSource` remains optional, so a future caller could omit the
  adapter and render the integration placeholder while build/tests stay green.
  Current `main.tsx` injects it correctly. Hardening the T2 prop or adding a
  production-entry smoke test is outside this T4-only change.
- Existing automated UI tests use the T2 preview adapter. The integrated Chrome
  run closes the current acceptance gap, but future regressions would benefit
  from an authorized production-entry test.
- The module-level adapter outlives a `GuidedDemoPage` remount while the UI
  idempotency cycle does not. Remounting the same adapter after a completed
  reset can replay a stale cycle-0 command. The single-page competition path
  does not remount, but a future router or live adapter needs a lifecycle design.
- Submission copy describes approval as clearing the fixture latch. The current
  observable implementation records approval and the simulated action, then
  changes health only during verification. Treat latch clearing as fixture
  narrative, not an independently observable process effect.
- Descriptor wording `Side effects: none` means no external/provider side
  effects; the commands intentionally mutate in-memory demo state and audit.
- Root `README.md` and `MEMORY.md` still describe the repository as
  planning-only. They were not modified because they are outside the T4 write
  boundary. This report is the durable scoped record of the integrated state.
- A Chrome full-page screenshot attempt exceeded the browser's five-second
  capture limit. Viewport rendering, DOM geometry, the complete interactive
  flow, and console checks passed; no new screenshot file was added outside the
  T4 path.
